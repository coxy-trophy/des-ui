# DesOS VM Prototype Execution Plan

> **For agentic workers:** Use superpowers:executing-plans inline. This is the
> disposable prototype the owner instructed us to proceed with; no production
> desktop functionality is being added. Steps use checkbox syntax for tracking.

**Goal:** Boot an isolated Ubuntu-based DesOS desktop prototype with target-native DEs-UI binaries.

**Architecture:** Signed Canonical cloud image, private qcow2 overlay, NoCloud
provisioning, loopback SSH and private QMP. Build frozen DEs-UI source in the guest.

**Tech Stack:** QEMU/KVM, Ubuntu 26.04 LTS, cloud-init, Rust/Cargo, existing Debian packaging.

**Spec:** `docs/superpowers/specs/2026-11-09-desos-vm-design.md`.

## Global constraints

- Experimental scripts, credentials, disks and logs stay in ignored private `target/desos-vm/`.
- Frozen desktop source `d462986`; preserve its runtime behavior and dependency lock.
- No host installation, kernel/boot/service changes, or use of private host state.
- Ubuntu-kernel baseline precedes unmodified upstream-kernel testing.
- Record actual results and resource limitations; guest success does not certify hardware.

## Review focus

- Only dedicated SSH/QMP endpoints can control the guest; no public listeners or host-key reuse.
- Image signature/hash verification must succeed before launch; original image stays unchanged.
- Source archive contains tracked source only, never host configuration or build credentials.
- Checkpoints are made with the guest stopped or an explicit consistent snapshot procedure.
- A failed build or graphical startup remains a failure in the report until verified fixed.

### Task 1: Verified guest baseline

- [x] Download pinned image/checksums/signature and verify the published signing-key fingerprint and image hash.
- [x] Create private overlay, guest-only credentials, limited provisioning endpoint and QEMU command record.
- [x] Boot; expect Ubuntu 26.04, working dedicated SSH and completed cloud-init; save evidence and a stopped-guest checkpoint.

### Task 2: Target-native desktop

- [x] Transfer a `git archive` of frozen tracked source and install guest build/runtime dependencies.
- [ ] Build using `Cargo.lock`; expect release build exit 0, and retain toolchain/package provenance.
- [ ] Run appropriate existing startup/package checks in Ubuntu and install guest-only packages.
- [ ] Start on virtual DRM; expect matching process hashes, readiness acknowledgement and a visible rendered desktop; preserve guest recovery access.

### Task 3: Record and review

- [ ] Record commands, source/image/binary identities, actual outcomes and remaining guest/hardware cases.
- [ ] Check host desktop/container continuity and review prototype controls and provenance.
- [ ] Commit documentation only; keep images/credentials private and the prototype available for the next kernel experiment.

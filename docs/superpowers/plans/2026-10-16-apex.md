# Apex implementation plan

> Subagent-driven development: each wave is independent modules built in parallel in
> git worktrees sharing one `target/`, with the parent owning main.rs, runtime.rs,
> settings.rs and config.rs integration and every merge.

Spec: ../specs/2026-10-16-apex-design.md

## Wave 1 (parallel)
- A **Palette from one accent** — theme.rs (+ Appearance section, config keys).
- B **Command blocks** — term.rs, term/blocks.rs, assets/shell-integration/.
- C **Compositor motion** — compositor crate: animated window geometry, materialise,
  workspace slide, reduced-motion, never while locked.
- D **Instruments and alerts** — sysmon.rs, sensors.rs, panels.rs: per-core, temps,
  fans, GPU, disk I/O, load, failed units, battery health; SysMon::take_alerts().
- E **Palette extensions** — palette.rs, launcher.rs, workflows.rs, commands.rs:
  SSH hosts, calculator, processes, units, user commands.
- F **Control socket and des-ui-ctl** — control.rs, bin/des-ui-ctl.rs, packaging.

Rule: a worker edits only its owned files, may add `mod` lines to main.rs, and writes
`docs/superpowers/handoff/<letter>.md` for anything the parent must wire.

## Wave 2 (after wave 1 merges)
- Phosphor shader (needs C's render path), window rules + scratchpad + PiP (C),
  SSH follow-the-machine (D's sampler abstraction), panel widgets (D's panels),
  boot continuity (compositor splash + Plymouth), portals (new des-portal crate),
  night light, clipboard history (E), AccessKit + on-screen keyboard, README.

## Rulings
- Fixed interface greys stay fixed (DESIGN.md); derivation covers terminal colours,
  caution, muted and glow only.
- Shell integration for command blocks is opt-out and never replaces the user's rc
  files; it sources them first.
- The control socket is the shell's, not the compositor's, and its vocabulary is a
  closed list; `state` is read-only JSON.

# Live terminal restoration across shell restart

User intent: restart the DEs-UI graphical shell during work without losing multiple running terminals. Existing saved desktop sessions restore folders/layout only and are insufficient.

Design: use a compositor-scoped private tmux server to own interactive shells and directly launched terminal commands. The graphical shell owns attach clients, not the actual work. Restart/crash detaches clients; new UI reconnects live sessions, without replaying commands. Runtime JSON contains only ordered terminal IDs, active/split arrangement and scratchpad identity; output/history remains in tmux memory. Restore bounded terminal history for the renderer. Existing direct PTY mode remains for tests, standalone shells and explicit opt-out. Surface unavailable/reconnect failures rather than claiming preservation.

Lifecycle: compositor creates a fresh mode0700 user-owned runtime directory, passes DES_UI_TERMINAL_DIR across shell replacements, and starts its own foreground `tmux -D` child in the compositor/watchdog process group. Clients use `-N` so a missing server cannot become an escaped replacement daemon. Startup waits for a private mode0600 socket and a bounded readiness probe; missing or unsupported tmux disables preservation. Compositor teardown explicitly kills only this private server, then reaps its retained child before hardware fast exit. The startup watchdog's process-group termination includes the foreground server even when destructors cannot run. No live-process restoration after logout/reboot; never attach arbitrary user tmux servers or sessions. GUI tab drop detaches; shell exit within a terminal ends that session. Existing saved desktop-session restoration stays separate.

UX: Settings → Session explains automatic reconnection and offers Keep terminals across shell restarts (on for new terminals by default). Setting changes affect new terminals; existing managed terminals remain reconnectable. On restore, show count and retain active pane/layout; recovery includes live sessions missing from metadata after abrupt UI crash. Scratchpad reconnects hidden. Never replay typed input, resurrect dead commands, or close live sessions to recover layout.

Dependencies: tmux >=3.3; already installed locally. Package/install checks document missing backend. Safe direct argv; user tmux config bypassed, own server only, bounded commands/output and metadata. Preserve cwd/foreground process tracking using actual pane shell PID, not attach-client PID. Forward shell integration OSC through tmux passthrough without breaking direct mode.

Verification: controlled terminal command PID/state survives detach and reconnect, multiple independent tabs and active/split metadata, explicit exit removes session, private-server cleanup on desktop exit, literal argv and bounded failure paths, frontend regression tests, full Rust build/tests. Unix bind restrictions may block real tmux integration here; record rather than hide failures.

Lifetime hardening: tmux runs foreground (-D) as a compositor child in the watchdog process group, with Linux parent-death SIGKILL and a parent-PID race check. Backend clients use -N to forbid daemonizing a replacement server. Hardware fast exit explicitly shuts the runtime down. Partial reconnect never overwrites previous layout metadata; a later restart can recover it.
